## 아이템 드랍 설정

기본값은 일반 바닥 아이템 생성 횟수 3배, 품질 인자 2배입니다.
모바일·Android에서는 오프라인 로비의 **아이템 드랍 → 설정**에서 변경합니다.
네이티브 실행에서는 `init.txt`에 아래 옵션을 기록합니다. 배수 옵션은
백분율 정수로 지정합니다(`150` = 1.5배).

| 옵션 | 기본값 | 범위 | 의미 |
| --- | ---: | ---: | --- |
| `hns_floor_item_rate` | 300 | 0–1000 | 일반 바닥 아이템 생성 횟수(%) |
| `hns_item_quality` | 200 | 0–1000 | 생성 품질 인자 배수(%) |
| `hns_item_min_level` | 0 | 0–50 | 생성 품질 인자의 최솟값 |
| `hns_good_item_chance` | 0 | 0–100 | 우수 아이템 생성 규칙을 적용할 추가 확률(%) |
| `hns_randart_chance` | 0 | 0–100 | 장비의 랜덤 아티팩트 생성을 시도할 추가 확률(%) |
| `hns_gold_amount` | 100 | 1–1000 | 골드 한 묶음의 수량 배수(%) |
| `hns_consumable_amount` | 100 | 1–1000 | 물약·스크롤·탄약 한 묶음의 수량 배수(%) |

예를 들어 바닥 아이템을 5배로 늘리고, 얕은 층의 최소 품질을 높이려면:

```ini
hns_floor_item_rate = 500
hns_item_quality = 200
hns_item_min_level = 15
```

변경 후 게임을 재시작·재개하면 새로 생성하는 아이템부터 적용합니다.
소모품 묶음 수량은 **금고·특수방을 포함한 새 바닥의 물약·스크롤·탄약**에
적용합니다. 예를 들어 5배면 물약 2개 묶음은 10개, 스크롤 3개 묶음은 15개입니다.
명시된 보상 수량을 정한 뒤 한 번만 곱합니다. 이미 생성된 층, 기존 아이템,
몬스터 소지 장비, 상점, 신의 선물, 획득의 두루마리는 변경하지 않습니다. 모바일 설정은
기기 내 모든 오프라인 캐릭터에 적용하며 공개 서버의 규칙은 바꾸지 않습니다.

바닥 생성량 0은 일반 바닥 아이템 생성을 끕니다. 아이템 금지 분기의
생성량은 계속 0이며, 배치 공간·아이템 슬롯이 부족하면 실제 수량이 줄어듭니다.
수량 배수는 반올림하며 골드·소모품 한 묶음은 최소 1개입니다.

품질 배수는 분기별 보정 이후 적용하며 일반 품질 인자의 상한 50을
유지합니다. D:1의 기본 품질 0을 높이려면 최소 품질을 설정하세요.
품질은 장비 종류·강화·브랜드·아티팩트 등 여러 확률식에 쓰이므로 강화 수치나
아티팩트 확률 자체의 배수가 아닙니다. 우수 아이템 판정 이후 랜덤 아티팩트
판정을 적용합니다. 아티팩트 설정은 무기·방어구·장신구·탈리스만에 적용하며,
아티팩트가 불가능한 종류나 생성 실패는 우수 아이템으로 대체합니다.
추가 확률 0%에서도 엔진의 기본 우수 아이템·아티팩트 확률은 유지합니다.

소모품 묶음 수량을 제외한 옵션은 기존 HNS와 같은 일반 랜덤 바닥 아이템만 조절합니다. 몬스터 전리품은 원래
소지품을 떨어뜨리는 기존 규칙을 유지합니다.

## 던전의 악의 제거

새 지형을 발견할 때 발생하던 악의 확률 판정과 낙하, 강제 순간이동,
경보 효과를 제거했습니다. 관련 지연 실행 상태, 위저드 명령, 힌트,
Ashenzari의 악의 방어 안내도 정리했습니다.

맵에 배치된 함정, 몬스터의 능력, 지옥 효과, Zot 시간 제한은 별개의
시스템이므로 기존 규칙을 따릅니다. 힌트 열거형의 기존 번호는 저장 파일
호환성을 위해 예약 상태로 유지합니다.

## 층 진입 시점으로 부활

사망 시 `Revive at the last level entry?`에서 `y`를 누르면 마지막 층 진입
시점으로 돌아갑니다. 횟수 제한은 없습니다. `n`을 누르면 기존 사망 처리를
진행하며, Felid의 남은 목숨 등 기존 부활 능력도 원래 규칙대로 적용됩니다.
자발적인 게임 종료, 던전 탈출, 승리에는 부활을 제안하지 않습니다.

층 진입 시 캐릭터와 모든 층의 저장 상태를 함께 보관합니다. 복귀하면 체력,
마력, 소지품, 경험치, 몬스터, 지형, 난수 상태를 포함해 그 이후의 진행을
되돌립니다. 체력과 마력은 해당 시점의 값으로 돌아가며 별도로 완전히
회복하지 않습니다. 계단 재진입, 포털, 낙하 등 층 이동마다 복귀 지점을
갱신합니다. 진입 효과 처리 도중 사망하면 이전 복귀 지점을 사용합니다.

복귀 지점은 캐릭터 저장 파일 안에 함께 저장하므로 게임을 껐다 켜도
유지됩니다. 새 캐릭터는 시작 시점을, 이 기능이 없던 버전의 저장 파일은
처음 불러온 시점을 최초 복귀 지점으로 사용합니다. 저장 파일 크기와 층 이동
시 저장 작업량은 증가합니다. 튜토리얼과 저장하지 않는 게임에는 적용하지
않습니다. 턴 단위 무르기는 아직 구현하지 않았습니다.

기본적으로 활성화되며, `init.txt`에서 다음 설정으로 끌 수 있습니다.

```ini
hns_revival = false
```

## 빌드 및 검증

Ubuntu / Debian 콘솔 빌드의 예입니다.
태그가 없는 체크아웃에서는 포함된 `source/util/release_ver` 파일의
`0.35-a0-hns`를 빌드 버전으로 사용합니다.

```sh
sudo apt-get update
sudo apt-get install build-essential pkg-config libncursesw5-dev \
    liblua5.4-dev libsqlite3-dev libpcre3-dev zlib1g-dev bison flex python3-yaml
git clone https://github.com/jackrevol/dcss-hns.git
cd dcss-hns/crawl-ref/source
make -j4
./crawl
```

테스트 및 코드 스타일 검사:

```sh
make -j4 catch2-tests
util/checkwhite -n
util/unbrace -n
```

타일 버전과 Windows 빌드는 [원본 설치 안내](../INSTALL.md)를 참고하세요.
원본과 같은 GPLv2+ 라이선스를 적용하며 기존 저작권 및 라이선스 고지를
유지합니다.

### 검증 기록 (2026-10-17)

- Ubuntu 22.04 / GCC 11.4.0에서 콘솔 실행 파일과 Catch2 테스트를 빌드했습니다.
- Catch2: 67개 테스트, 9,299개 검증을 모두 통과했습니다.
- 기존 `seed_explorer.lua` 스크립트로 시드 1~5의 D:1~D:5를 생성하고
  바닥 아이템 배치를 확인했습니다.
- 수정 파일의 `checkwhite`, `unbrace`, `git diff --check`를 통과했습니다.
- Windows 및 타일 버전은 빌드하지 않았습니다.

### 부활 기능 추가 검증 (2026-10-17)

- MSYS2 / MinGW-w64에서 Windows 타일 실행 파일을 빌드했습니다.
- Windows Catch2 실행 파일: 69개 테스트, 9,332개 검증을 모두 통과했습니다.
- 부활 테스트에서 저장 후 재로드, 반복 복원, 다른 층의 아이템·몬스터 상태
  복원, 새로 생성된 층 제거, 복귀 지점 갱신을 확인했습니다.
- `crawl.exe -headless -builddb` 실행을 통과했습니다.
- 변경 파일의 `checkwhite`, `unbrace`, `git diff --check`를 통과했습니다.
- 실제 사망 확인창을 조작하는 수동 플레이 검증은 수행하지 않았습니다.
